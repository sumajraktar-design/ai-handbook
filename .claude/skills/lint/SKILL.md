# 手册体检

先做程序能做的检查，再做需要理解的检查。只报告问题，修改前先让用户确认。

## 第一轮：机械检查（写个小脚本跑，不要靠肉眼）

- 每个文件的 frontmatter 字段齐全，`id` 与文件名一致，`group` 和 `priority` 取值合法
- `related` 里的每个 id 都有对应文件
- 正文里的相对链接都能找到目标文件
- `wiki/index.md` 列出的页面和 `wiki/concepts/` 里的文件一一对应
- `related` 的双向性：A 关联 B 而 B 没有关联 A 的，列出来
- `sources` 为空的页面

## 第二轮：内容检查（需要阅读理解）

- **矛盾**：两个页面对同一件事说法不一致
- **过时**：提到具体产品、版本、价格、"目前""最新"的地方，`updated` 超过 6 个月的，标出来请用户核实
- **缺口**：多个页面都提到、但没有独立页面的概念
- **质量**：一句话定义说不清楚的、某个二级标题下的内容离开上下文就读不懂的

## 输出

按"机械问题 / 内容问题"分两组，每条写清：哪个文件、什么问题、建议怎么改。
